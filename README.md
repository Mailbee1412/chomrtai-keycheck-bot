# ChomRtai Key Check Bot

บอทดิสคอร์ดสำหรับร้านขายคีย์ **LinkAPI** ประกอบด้วย 3 ระบบหลัก

- **🔑 เช็คคีย์** — ผู้ใช้กดปุ่ม "ตรวจสอบคีย์" แล้ววางคีย์ `sk-...` เพื่อดูจำนวนข้อความคงเหลือในแต่ละโมเดล (เห็นผลเฉพาะเจ้าของคีย์)
- **🛒 ร้านค้า (Shop)** — แผงสินค้า, สร้างห้องออเดอร์อัตโนมัติ, แนบสลิป, ตรวจสลิป/เทียบยอดอัตโนมัติ และสรุปยอดรายวัน
- **🆘 ฟอร์มแจ้งปัญหา (Support Form)** — ปุ่มแจ้งปัญหา 2 สเต็ป, แนบรูปได้ และปิดเคสโดยทีมงาน

> เช็คคีย์ทำผ่าน **ปุ่มเท่านั้น** (ไม่มี slash command) ส่วนร้านค้าใช้ slash command `/ตั้งราคา` ในการตั้งเรตราคา

---

## 1. สิ่งที่ต้องมี

- Node.js 20 ขึ้นไป
- บอทดิสคอร์ด (สร้างที่ https://discord.com/developers/applications)

## 2. เตรียมบอท

1. ไปที่ Developer Portal → **New Application** → แท็บ **Bot**
2. กด **Reset Token** แล้วคัดลอกโทเคน
3. คัดลอก **Application ID** จากแท็บ General Information
4. เปิด **Privileged Gateway Intents**
   - **Message Content Intent** — จำเป็นเมื่อเปิดโหมดเช็คอัตโนมัติ (`LINKAPI_MESSAGE_CHECK=true`)
   - **Server Members Intent** — แนะนำเปิด เพื่ออ่าน role ของสมาชิกได้ครบ

## 3. ติดตั้ง

```bat
copy .env.example .env
```

แก้ `.env` ใส่ค่าจำเป็น:

```env
DISCORD_TOKEN=โทเคนของบอท
DISCORD_CLIENT_ID=Application_ID
```

> ถ้าใส่ `DISCORD_GUILD_ID` คำสั่ง `/ตั้งราคา` จะลงทะเบียนที่เซิร์ฟเวอร์นั้นทันที (ไม่ต้องรอ global)

## 4. เชิญบอทเข้าเซิร์ฟ

ที่แท็บ **OAuth2 → URL Generator** เลือก scope `bot` และ `applications.commands` แล้วให้สิทธิ์:

- View Channels
- Send Messages
- Send Messages in Threads
- Read Message History
- Embed Links
- Attach Files
- Manage Messages (ลบข้อความที่มีคีย์ / จัดการแท็กเคส)
- Manage Channels (สร้างห้องออเดอร์)
- Manage Threads (ล็อกเคสเมื่อปิดงาน)
- Create Private Threads (โหมด thread)

## 5. รันบอท

ดับเบิลคลิก `start.bat` หรือ

```bat
npm install
npm start
```

> บอทมี **single-instance lock** (`data/bot.lock`) — ถ้ามีบอทรันอยู่แล้วจะไม่เปิดซ้ำ

## 6. วิธีใช้งาน — เช็คคีย์

1. บอทโพสต์ข้อความต้อนรับ + ปุ่ม **🔑 ตรวจสอบคีย์** ในช่อง `LINKAPI_WELCOME_CHANNEL_ID`
2. ผู้ใช้กดปุ่ม → เปิดโมดัล "เช็คโควต้าคีย์" → วางคีย์ `sk-...` (ใส่หลายคีย์พร้อมกันได้)
3. บอทตอบผลแบบ **เห็นเฉพาะผู้ใช้คนนั้น** (ephemeral)

ผลลัพธ์จะแสดงหัวข้อตาม **ชนิดคีย์ที่ตรวจพบ** และเหลือรายโมเดล:

```
🥃 เช็คโควต้าคีย์ · Long Island
✧ ───────────── ✧
◦ โควตา : ♾️ ไม่จำกัด
◦ จำนวนโมเดล : 2 โมเดล
◦ `[次]gemini-3.1-pro-preview` — **238** ข้อความ (ใช้ไป 12)
◦ `[次]gemini-3.8-flash` — **320** ข้อความ
✧ ───────────── ✧
```

หัวข้อจะเปลี่ยนตามชนิดคีย์:

| โมเดลในคีย์ | แสดงเป็น |
| --- | --- |
| Gemini Pro + Flash | 🥃 Long Island |
| Gemini Flash | 🍹 Margarita |
| Claude + Gemini | 🍷 Cosmo |
| Claude | 🍸 Angel Shot |
| อื่น ๆ / ไม่ทราบ | 🎟️ LINKAPI |

> โมเดลที่เหลือไม่จำกัดจะแสดงโควตาว่า `♾️ ไม่จำกัด` และโมเดลที่เหลือน้อย (≤ 20) จะมี ⚠️ กำกับ

### โหมดเช็คอัตโนมัติในแชท (ไม่บังคับ)

ตั้ง `LINKAPI_MESSAGE_CHECK=true` เพื่อให้บอทอ่านข้อความในห้องและเช็คคีย์ให้เอง (ลบข้อความต้นทางตาม `LINKAPI_PRIVATE_MODE`) — ค่าเริ่มต้นปิด เพื่อให้ใช้ปุ่มเท่านั้น

### โมเดลที่ถูกนับ

บอทจะนับ **เฉพาะโมเดลที่ขึ้นต้นด้วย `[次]`** เท่านั้น (โมเดลคิดตามจำนวนครั้ง) โมเดล `[SP]`, `[free]` และโมเดลคิดตามโทเคนจะถูกข้าม ถ้าต้องการนับโมเดลที่ไม่มี `[次]` ให้ตั้งราคาผ่าน `LINKAPI_PRICE_OVERRIDES`

### ไฟล์ Excel

ผลการเช็คทุกครั้งจะถูกบันทึกลง `data/linkapi-keys.xlsx` (กำหนดตำแหน่งเองได้ด้วย `LINKAPI_EXCEL_PATH`) ถ้าอยากให้ระบุชื่อบัญชี/อีเมลในไฟล์ ให้ตั้ง `LINKAPI_ACCESS_TOKEN` และ `LINKAPI_USER_ID`

### ตัวแปรที่สำคัญ (.env)

| ตัวแปร | ความหมาย |
| --- | --- |
| `LINKAPI_CHANNEL_IDS` | จำกัดให้เช็คได้เฉพาะบางห้อง (คั่นด้วย `,` ปล่อยว่าง = ทุกห้อง) |
| `LINKAPI_WELCOME_CHANNEL_ID` | ช่องสำหรับโพสต์ข้อความต้อนรับ + ปุ่มตรวจสอบคีย์ (โพสต์ครั้งเดียวตอนบอทออนไลน์) |
| `LINKAPI_MESSAGE_CHECK` | `true` = เช็คอัตโนมัติเมื่อพิมพ์คีย์ในแชท (ค่าเริ่มต้น `false`) |
| `LINKAPI_PRIVATE_MODE` | `thread` (ค่าเริ่มต้น) / `dm` / `off` — ใช้กับโหมดเช็คอัตโนมัติ |
| `LINKAPI_MAX_KEYS` | จำนวนคีย์สูงสุดต่อครั้ง (ค่าเริ่มต้น 10) |
| `LINKAPI_STRICT_ACCOUNT` | `true` = เช็คได้เฉพาะคีย์ของบัญชีที่ล็อกอิน |
| `LINKAPI_MODEL_LIMITS` | รายชื่อโมเดลสำรอง กรณีคีย์ไม่ได้ตั้ง Model Limits |
| `LINKAPI_PRICE_OVERRIDES` | ราคาต่อครั้งที่บังคับเองสำหรับโมเดลที่ไม่มี `[次]` |
| `LINKAPI_QUOTA_UNIT` | หน่วยโควตาที่เว็บแสดง (ค่าเริ่มต้น `USD`) |
| `LINKAPI_QUOTA_PER_UNIT` | ตัวหารแปลงโควตาดิบเป็นหน่วยที่เว็บแสดง (ค่าจริง 500000) |
| `LINKAPI_LOW_ALERT` | แจ้งเตือนเมื่อเหลือต่ำกว่าค่านี้ |
| `LINKAPI_ACCESS_TOKEN` / `LINKAPI_USER_ID` | บัญชีแอดมินผู้ใช้ เพื่อให้ Excel ระบุชื่อบัญชี/อีเมล |
| `LINKAPI_STORE_FULL_KEY` | `true` = เก็บคีย์เต็มลง Excel |
| `LINKAPI_EXCEL_PATH` | ตำแหน่งไฟล์ Excel (ว่าง = `data/linkapi-keys.xlsx`) |

## 7. ร้านค้า (Shop)

1. บอทโพสต์แผงสินค้าในช่อง `SHOP_CHANNEL_ID` (ปุ่มเลือกสินค้า)
2. ผู้ใช้กดสินค้า → บอทสร้าง **ห้องออเดอร์ส่วนตัว** ในหมวด `SHOP_CATEGORY_ID` พร้อม QR (`SHOP_QR_IMAGE_PATH`)
3. ผู้ใช้กดปุ่มแนบสลิป → เลือกจำนวนข้อความ → อัปโหลดรูปสลิป
4. บอทอ่านยอดจากสลิปอัตโนมัติ แล้วคูณราคาเป็น `(ราคาต่อหน่วย ÷ หน่วย) × จำนวนข้อความ` เพื่อเทียบกับยอดสลิป
5. ถ้า **ยอดไม่ตรง**, **สลิปซ้ำ**, **สลิปเคยถูกใช้คนละห้อง** หรือ **สลิปเก่าเกิน `SHOP_SLIP_MAX_AGE_HOURS`** → บอทแจ้งทีมงานในช่อง `SHOP_ORDER_LOG_CHANNEL_ID` (แท็กทีมงานถ้า `SHOP_MENTION_STAFF=true`)
6. ส่งสรุปยอดรายได้รายวันตามเวลา `SHOP_DAILY_SUMMARY_TIME` (เขตเวลา `SHOP_TIMEZONE`)

### คำสั่ง `/ตั้งราคา` (ทีมงานเท่านั้น)

ราคาของสินค้าเป็น **เรตต่อ 100 ข้อความ** (`pricePer=100`)

- `/ตั้งราคา` — ดูราคาบริการทั้งหมด
- `/ตั้งราคา product:<บริการ>` — ดูราคาของบริการนั้น
- `/ตั้งราคา product:<บริการ> price:<ตัวเลข>` — ตั้งราคาต่อหน่วย (บาท)

### ตัวแปรที่สำคัญ (.env)

| ตัวแปร | ความหมาย |
| --- | --- |
| `SHOP_CHANNEL_ID` | ช่องวางแผงร้านค้า (ว่าง = ไม่โพสต์แผง) |
| `SHOP_CATEGORY_ID` | หมวดหมู่สำหรับสร้างห้องออเดอร์ (ว่าง = ใช้หมวดเดียวกับช่องร้าน) |
| `SHOP_ORDER_LOG_CHANNEL_ID` | ช่องส่งสรุปยอด/แจ้งเตือนออเดอร์ (ว่าง = ไม่ส่ง) |
| `SHOP_STAFF_ROLE_IDS` | Role ทีมงานร้าน (ว่าง = ใช้ `SUPPORT_FORM_STAFF_ROLE_IDS`) |
| `SHOP_MENTION_STAFF` | `true` = แท็กทีมงานในห้องออเดอร์ (ค่าเริ่มต้น `true`) |
| `SHOP_QR_IMAGE_PATH` | path ไฟล์รูป QR (ว่าง = ไม่แนบ) — เช่น `assets/shop-qr.png` ดูวิธีวางไฟล์ใน [`assets/README.md`](assets/README.md) |
| `SHOP_CURRENCY_SYMBOL` | สัญลักษณ์สกุลเงิน (ค่าเริ่มต้น `฿`) |
| `SHOP_TIMEZONE` | เขตเวลานับรอบวัน (ค่าเริ่มต้น `Asia/Bangkok`) |
| `SHOP_DAILY_SUMMARY_TIME` | เวลาส่งสรุปรายวัน `HH:MM` (ค่าเริ่มต้น `23:59`) |
| `SHOP_SLIP_VERIFY_PROVIDER` | ผู้ให้บริการอ่านสลิป: `easyslip` (ค่าเริ่มต้น) หรือ `gemini` |
| `SHOP_SLIP_VERIFY_KEY` | คีย์ผู้ให้บริการอ่านสลิป (ว่าง = ปิดการอ่านสลิปอัตโนมัติ ใช้ยอดที่ผู้ซื้อกรอก) |
| `SHOP_SLIP_VERIFY_BASE` | เปลี่ยน base URL ของผู้ให้บริการ (ว่าง = ค่าเริ่มต้น) |
| `SHOP_SLIP_VERIFY_MODEL` | โมเดล Gemini (ใช้เมื่อ provider เป็น `gemini`) |
| `SHOP_SLIP_MAX_AGE_HOURS` | ถือว่าสลิป "เก่า" ถ้าโอนเกินกี่ชั่วโมง (แจ้งเตือนทีมงาน, ค่าเริ่มต้น 24) |

## 8. ฟอร์มแจ้งปัญหา (Support Form)

บอทมีระบบ "แจ้งปัญหาใช้งาน" แบบ 2 สเต็ป:

1. ผู้ใช้กดปุ่ม **แจ้งปัญหา** ในช่องที่ตั้งไว้ (`SUPPORT_FORM_CHANNEL_ID`)
2. **สเต็ป 1 (1/2)** เปิดฟอร์มให้เลือก/กรอก 5 ช่อง:
   - **วิธีเปิด** — เลือก `Termux` / `Irole`
   - **อุปกรณ์** — เลือก `iOS` / `Android` / `PC — Windows` / `PC — macOS`
   - **โมเดลที่ใช้** — พิมพ์เอง
   - **Jailbreak ที่ใช้** — พิมพ์เอง
   - **ปัญหาและคำถาม** — พิมพ์เอง (อธิบายละเอียด)
3. เมื่อส่ง บอทจะสร้างโพสต์เคสในช่องปลายทางทันที (เป็นข้อความธรรมดา อ่านง่าย ไม่มีกรอบ embed) พร้อม
   - แท็ก **รอแก้ไข**
   - แท็กคนแจ้ง + Role ทีมงาน (`SUPPORT_FORM_NOTIFY_ROLE_IDS`)
   - ปุ่ม **แก้ไขแล้ว / ปิดเคส** ของทีมงาน
4. **สเต็ป 2 (2/2) แนบรูป (ไม่บังคับ)** — ในข้อความยืนยันส่วนตัวจะมีปุ่ม `📎 แนบรูป (ถ้ามี)` กดแล้วเลือกไฟล์รูปได้เลยไม่ต้องใช้ลิงก์ บอทจะส่งรูปเข้าโพสต์ให้
5. ทีมงานกดปุ่ม **แก้ไขแล้ว / ปิดเคส** ปุ่มเดียว → เปลี่ยนแท็กเป็น **แก้ไขแล้ว** และล็อกช่องเป็นดูได้อย่างเดียว

> โมดัลของ Discord จำกัด **5 ช่องต่อโมดัล** และเปิดโมดัลซ้อนจากผลส่งโมดัลไม่ได้ จึงแบ่งเป็น 2 สเต็ป: สเต็ป 1 กรอกข้อมูลหลัก สเต็ป 2 แนบรูป
>
> แนะนำให้ช่องปลายทาง (`SUPPORT_FORM_TARGET_CHANNEL_ID`) เป็น **ฟอรัม (Forum)** เพื่อให้ใช้แท็กและล็อกช่องได้เต็มรูปแบบ

### ตัวแปรที่เกี่ยวกับฟอร์ม (.env)

| ตัวแปร | ความหมาย |
| --- | --- |
| `SUPPORT_FORM_CHANNEL_ID` | ช่องสำหรับวางปุ่ม "แจ้งปัญหา" |
| `SUPPORT_FORM_TARGET_CHANNEL_ID` | ช่องปลายทางที่สร้างโพสต์เคส (แนะนำเป็นฟอรัม) |
| `SUPPORT_FORM_TARGET_TYPE` | `text` หรือ `forum` |
| `SUPPORT_FORM_FORUM_TAG_ID` | ID แท็กฟอรัม เรียงตามสถานะ `pending,in-progress,resolved` |
| `SUPPORT_FORM_BUTTON_LABEL` | ข้อความบนปุ่มเปิดฟอร์ม |
| `SUPPORT_FORM_ALLOWED_ROLE_IDS` | Role ที่กดปุ่มแจ้งปัญหาได้ (ว่าง = ทุกคน) |
| `SUPPORT_FORM_NOTIFY_ROLE_IDS` | Role ทีมงานที่จะถูกแท็กในโพสต์ใหม่ |
| `SUPPORT_FORM_STAFF_ROLE_IDS` | Role ที่กดปุ่มปิดเคสได้ |
